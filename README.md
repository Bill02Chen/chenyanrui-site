# chenyanrui-site

Personal website of Yanrui Chen — one site, two languages.

- **English** → `/` (repo root)
- **中文** → `/zh/`

Built with plain HTML, CSS and JavaScript. No build step, no dependencies,
no framework. Every word lives in a JSON file, so the two language versions are
generated by one shared renderer.

```
index.html            English page
data/site.json        English content
zh/index.html         Chinese page
zh/data/site.json     Chinese content
assets/styles.css     Design system
assets/app.js         Renderer — never contains user-facing copy
tools/                Local content and render checks
.nojekyll             Tells GitHub Pages to serve files as-is
```

## Publishing on GitHub Pages

1. Create an empty repository on GitHub (public). Do **not** add a README,
   `.gitignore` or licence — this folder already has them.
2. Push this folder to it (see the commands under "First push").
3. In the repository, open **Settings → Pages**.
4. Under **Build and deployment → Source**, choose **Deploy from a branch**.
5. Set **Branch** to `main` and the folder to `/ (root)`, then **Save**.
6. Wait for the first deployment (about a minute). The site appears at:

   ```
   https://<your-username>.github.io/<repository-name>/
   ```

   The Chinese version is at the same URL plus `zh/`.

Every later `git push` to `main` redeploys automatically.

### First push

```sh
git init -b main
git add -A
git commit -m "Personal website: English and Chinese"
git remote add origin https://github.com/<your-username>/<repository-name>.git
git push -u origin main
```

GitHub no longer accepts your account password over HTTPS. When prompted for a
password, paste a **personal access token** with the `repo` scope instead
(GitHub → Settings → Developer settings → Personal access tokens). The macOS
keychain will remember it after the first successful push.

### Custom domain (optional)

1. Create a file named `CNAME` in this folder containing only the domain, e.g.
   `yanruichen.com`, and push it.
2. At your DNS provider, add a `CNAME` record for `www` pointing to
   `<your-username>.github.io`, plus `A` records for the apex domain pointing to
   `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`.
3. In **Settings → Pages**, enter the domain and enable **Enforce HTTPS**.

## Editing content

All text is in the two JSON files. Both files must keep identical keys — only the
values are translated. A project entry looks like this:

```json
{
  "title": "Project name",
  "period": "Mar 2026",
  "context": "CUHK",
  "tagline": "One line naming the problem.",
  "highlights": ["Two to five bullets, each carrying its own metric."],
  "stack": ["PyTorch", "Redis"]
}
```

To make the "Download CV" button appear, set `hero.resumeUrl` in `data/site.json`
(and its counterpart in `zh/data/site.json`) to a PDF path inside this repo. While
empty, the button stays hidden so the site never offers a broken download.

## Local preview

The pages fetch their content as JSON, so they must be served over HTTP —
opening `index.html` from the file system does not work.

```sh
python3 -m http.server 8000
```

Then open <http://localhost:8000/> or <http://localhost:8000/zh/>.

## Checks

`tools/audit_content.py` reads the source résumés from a parent folder and is
meant to run in the original working directory. It verifies that every number on
the site traces back to a résumé and that both language versions describe the
same experiences.

```sh
python3 tools/audit_content.py
node tools/render_test.mjs
```
